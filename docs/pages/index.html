Architecture highlights

Legacy terminal engine, Telegram-native experience

C engine via PTY

Each player session drives the original ReLarn binary through a protected subprocess and pseudo-terminal adapter.

Inline UI state machine

Terminal prompts, shops, inventories, numeric inputs, and confirmations are translated into Telegram inline keyboards.

Rendered retro maps

ANSI terminal output is rasterized into stable images so the grid remains readable across Telegram clients.

Persistent sessions

MongoDB stores serialized engine state per chat, with optimistic locking to reject stale button callbacks.

    Deployment note

    Why tgLarn is not playable directly in the browser?

    tglarn keeps dedicated per-user ReLarn C subprocess sessions on EC2 and persists state through MongoDB. That runtime model depends on secure server-side process management, PTY I/O, and Telegram callback validation. GitLab Pages is a static hosting environment, so this page serves as a high-fidelity preview and a direct entry point to the production Telegram bot.

    The repository is not large by raw line count, but the integration complexity is substantial because it combines:

    • a legacy C roguelike engine;
    • a Python layer that drives the C engine through subprocesses and PTYs;
    • a terminal capture and rendering adapter;
    • Telegram bot handlers and an inline UI state machine;
    • persistence and session logic;
    • Docker, deployment, and CI wiring;
    • tests around the process boundary, prompts, sessions, and rendering.
